# 数值计算题目提交注意事项

数值计算题目除了算法是否正确，也会检查输入处理、误差控制和输出格式。提交前可按下表逐项检查。

| 现象 | 常见原因 | 检查方法 |
|------|----------|----------|
| 样例结果正确但判错 | 输出混入提示语、调试内容或多余文本 | 让标准输出只包含题目要求的内容 |
| 浮点结果接近但不通过 | 中间步骤过早舍入，或输出精度不符合要求 | 对照题面规定的误差和格式检查计算与输出 |
| 迭代结果不稳定 | 收敛条件、误差界或区间更新不符合题目要求 | 按题面推导每一步更新，并检查边界情况 |
| 个别输入失败 | 只按样例输入编写解析，或漏掉定义域与边界值 | 检查完整输入格式、合法范围和特殊边界 |
| 线性方程组求解异常 | 主元选择、行交换或消元更新有误 | 每次消元后核对矩阵和右端项是否执行了相同的行变换 |

## 提交前检查

1. 使用 G++ 编译 `main.cpp`，用题面样例逐字符核对输出格式。
2. 对函数近似或迭代算法，检查题目给定的初值、区间、停止条件和精度要求。
3. 对矩阵算法，检查行交换对整行及右端项的影响。
4. 删除调试输出，并确认程序从标准输入读取、向标准输出写入。

## 精度与评判记录

- 18998 已通过：当前使用范围缩放和对数级数，全程使用 `double`，按 14 位小数输出。扩展精度版本未通过，不能用“内部精度更高”代替 OJ 核验。
- 19001 已通过：按《实用数值计算方法》第 5.3 节的算法保存近、远步长，初始化为 `farStep=(b-a)*golden`、`nearStep=farStep*golden`；每轮先令 `farStep=nearStep`，再令 `nearStep=farStep*golden`，复用已有分割点和函数值。以 `nearStep < 0.4e-8` 停止。不要用重新计算端点距离替代这一递推过程。
- 黄金分割题用 G++ 内建函数 `__builtin_exp` 计算目标函数，并在函数值相等时保留右侧区间。极小值附近的相减会放大指数函数最后几位的差异；不同数学库可能得到不同的最终端点，须以目标 OJ 上的源码核验和评判结果确认。

## 页面超时

单个操作页持续加载或 CDP 求值超时，不能直接认定 OJ 整体不可用。本次重建独立 mainMenu 操作页后恢复响应。出现此情况时，先保留现有提交状态，重建本次操作页并检查记录，再决定是否重交。
